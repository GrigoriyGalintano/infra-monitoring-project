# Анализ сетевого трафика

## Дамп

[traffic.pcapng](traffic.pcapng) содержит обезличенную копию реального захвата трёх HTTP-соединений к публичному API httpbin. Запросы отправлены через curl, захват выполнен Wireshark Dumpcap. В копии 30 Ethernet-пакетов, размер 4200 байт. Интервал между первым и последним пакетом составляет около 1,81 секунды.

SHA256:

```text
68603d5f5f4f02340601b3bef9000797bf444f728b986c50b771eca1f5adf91d
```

## Обезличивание

Поскольку дамп публикуется в учебном репозитории, сетевые идентификаторы заменены. Показанные ниже IP принадлежат диапазонам для документации и не являются реальными адресами участников:

| Адрес в дампе | Роль |
| --- | --- |
| `192.0.2.10` | Обезличенный HTTP-клиент |
| `198.51.100.20` | Обезличенный адрес сервера httpbin |

В ответе `/get` также заменено поле `origin`, которое может содержать внешний адрес клиента. Удалены идентификаторы трассировки запросов. MAC-адреса и клиентские TCP-порты заменены учебными значениями. Убраны названия интерфейсов, их GUID, сведения об ОС и оборудовании. Абсолютные временные отметки и HTTP-заголовки Date заменены условными значениями; интервалы между пакетами сохранены. В публикацию включены только HTTP-соединения, без TLS и других сеансов.

Методы, URL-пути, HTTP-коды и последовательность пакетов сохранены. Длины HTTP-ответов и согласованность TCP-потоков сохранены. Контрольные суммы IPv4 и TCP пересчитаны и проверены.

## Методы и коды ответов

| Метод | URL | Ответ | Кадры запроса и ответа |
| --- | --- | --- | --- |
| GET | `http://httpbin.org/get` | `200 OK` | 4 и 6 |
| POST | `http://httpbin.org/status/201` | `201 Created` | 11 и 14 |
| GET | `http://httpbin.org/status/404` | `404 Not Found` | 19 и 22 |

Использованы GET и POST. Код 200 означает успешный ответ, 201 обозначает создание ресурса, 404 обозначает отсутствие ресурса. Эндпоинты `/status/201` и `/status/404` намеренно возвращают выбранный код; создание ресурса в этом опыте не выполнялось.

## Фильтрация

Откройте дамп в Wireshark и примените фильтры отображения:

```text
http
http.request
http.response
http.request.method == "POST"
http.response.code >= 400
ip.addr == 192.0.2.10
```

Фильтр `http` показывает шесть пакетов с HTTP-запросами и ответами. Остальные пакеты обеспечивают работу TCP. Для захвата, содержащего HTTPS, применим фильтр `http || tls`, однако без ключей сеанса он не раскрывает зашифрованные методы и статусы.

Проверка сохранённого файла через TShark:

```bash
tshark -n -r reports/traffic.pcapng \
  -Y 'http.request or http.response' \
  -T fields -E header=y \
  -e frame.number -e ip.src -e ip.dst \
  -e http.request.method -e http.request.uri -e http.response.code
```

## Повторение опыта

Сначала определите активный интерфейс и текущий IPv4 сервера. Подставьте их в локальный фильтр захвата. Реальные адреса не требуется записывать в README или публиковать без обезличивания.

```bash
dumpcap -D
nslookup httpbin.org
```

Запустите захват на выбранном интерфейсе с ограничением на адрес API и TCP-порт 80. Во втором терминале выполните:

```bash
curl -X GET http://httpbin.org/get
curl -X POST http://httpbin.org/status/201
curl -X GET http://httpbin.org/status/404
```

В PowerShell используйте `curl.exe`. Перед публикацией новой копии удалите реальные IP из IP-заголовков и тел ответов, MAC, метаданные компьютера и идентификаторы запросов. Сырые дампы оставляйте локально.
